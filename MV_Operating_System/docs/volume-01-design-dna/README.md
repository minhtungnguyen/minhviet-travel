# VOLUME 01 — DESIGN DNA

**Project:** Minh Việt Travel Platform  
**Status:** Active design constitution  
**Version:** 1.0 — Batch 01  
**Authority:** Mandatory for all public website, CMS, CRM, booking, AI and mobile interfaces

---

## 1. Purpose

Volume 01 defines the visual and interaction DNA of Minh Việt Travel Platform.

This volume exists to prevent the product from becoming:

- a generic Vietnamese travel-agency website;
- a yellow promotional landing page;
- a crowded OTA-style catalogue;
- a collection of unrelated AI-generated components;
- a template-driven interface without a consistent product identity.

This volume is not a mood board. It is not optional inspiration. It is a binding design specification.

Every designer, developer and AI coding agent must use it as the source of truth before creating or modifying user interfaces.

---

## 2. Product Positioning Expressed Through Design

Minh Việt Travel Platform must be perceived as:

1. A professional travel operating platform.
2. A trusted travel partner for individuals, companies and institutions.
3. A technology-enabled travel company.
4. A premium but approachable Vietnamese brand.
5. A platform capable of serving leisure travel, corporate travel, MICE and complex group operations.

The interface must not communicate “cheap tour seller”.

The interface must communicate:

> Trust, operational capability, curation, calm confidence and modern travel technology.

---

## 3. Non-negotiable Design Direction

### 3.1 The website is not yellow

Gold and yellow may remain part of the brand identity, but they must not dominate page surfaces.

Forbidden by default:

- full-page yellow backgrounds;
- yellow hero sections;
- yellow navigation bars;
- multiple yellow cards in one viewport;
- yellow gradients used as decoration;
- yellow buttons repeated across the page;
- gold borders around every component.

Brand color is an accent, not a canvas.

### 3.2 The primary visual foundation

The interface must primarily use:

- white and restrained neutral surfaces;
- deep navy for authority and primary actions;
- subtle gold accents for brand recognition;
- strong typography and photography;
- generous whitespace;
- low visual noise;
- clear information hierarchy.

### 3.3 Premium does not mean decorative

Premium quality must come from:

- proportion;
- spacing;
- typography;
- image selection;
- restrained color;
- precise alignment;
- consistent interaction;
- editorial composition.

Premium quality must not come from:

- excessive gradients;
- ornamental gold;
- glassmorphism everywhere;
- heavy shadows;
- oversized rounded corners;
- animated decoration;
- luxury clichés.

## 4. Core Design Principles

### Principle 01 — Clarity before decoration

The user must understand the page purpose, primary content and next action immediately.

### Principle 02 — Trust before excitement

Travel content may inspire, but the interface must first feel credible, accurate and operationally dependable.

### Principle 03 — Curation before abundance

Do not show everything at once. Present the most relevant choices and provide progressive discovery.

### Principle 04 — Typography before color

Use scale, weight, spacing and alignment to establish hierarchy before adding color.

### Principle 05 — Photography before illustration

High-quality destination and experience photography is the primary emotional medium. Decorative travel illustrations are secondary and must be used sparingly.

### Principle 06 — Whitespace is functional

Whitespace separates decisions, reduces cognitive load and increases perceived quality. It is not wasted space.

### Principle 07 — One dominant action per section

Each section must have one clear primary intent. Secondary actions must be visually subordinate.

### Principle 08 — Technology should feel invisible

AI and automation must simplify travel decisions. They must not turn the interface into a futuristic control panel.

### Principle 09 — Enterprise capability without enterprise heaviness

Corporate and MICE services must feel structured and dependable without resembling outdated government or ERP software.

### Principle 10 — Consistency before novelty

New components must reuse established patterns unless a documented user need justifies a new pattern.

## 5. Required Experience Attributes

Every important public-facing screen must target the following attributes:

| Attribute | Required expression |
|---|---|
| Trustworthy | Clear information, policies, contacts, pricing context and operational proof |
| Premium | Controlled composition, high-quality images, strong typography and restraint |
| Modern | Contemporary layout, responsive behavior and polished interactions |
| Calm | Limited simultaneous calls to action and low visual noise |
| Professional | Precise wording, consistent spacing and complete service information |
| Travel-led | Destinations, experiences, itineraries and human moments remain central |
| Technology-enabled | Search, recommendation and AI assistance feel useful and contextual |
| Vietnamese | Local understanding and service warmth without visual clichés |
| International | Visual quality and usability must meet global product expectations |

## 6. Design Hierarchy of Authority

When documents or implementations conflict, apply this order:

1. Volume 00 — Project Foundation and scope.
2. Volume 01 — Design DNA.
3. Approved product requirements.
4. Approved page specifications.
5. Existing component library.
6. Existing implementation.
7. AI-generated suggestions.

Existing code is not automatically correct. If existing code conflicts with Volume 01, the conflict must be documented and corrected through an approved implementation task.

---

## 7. How Claude Code Must Use This Volume

Before creating or modifying UI, Claude Code must:

1. Read `README.md`.
2. Read `MANIFEST.md`.
3. Read all mandatory chapters listed for the requested task.
4. Inspect existing design tokens, Tailwind configuration and reusable components.
5. Identify conflicts between the current interface and Volume 01.
6. Produce a concise implementation plan.
7. Implement only the approved scope.
8. Run the design acceptance checklist.
9. Report remaining violations.

Claude Code must not reinterpret “premium travel” as a yellow or gold-heavy interface.

Claude Code must not use generic travel templates as the default design reference.

---

## 8. Immediate Failure Conditions

A design is rejected without scoring if any of the following occurs:

- the main page background is yellow or gold;
- the hero is dominated by yellow;
- the screen resembles a discount-tour landing page;
- multiple unrelated CTA colors compete in one viewport;
- cards use heavy shadows and thick decorative borders;
- travel stock imagery feels staged, generic or low quality;
- the layout is crowded with banners, badges and promotions;
- the same rounded-card treatment is applied to every element;
- AI elements dominate the travel experience without user need;
- mobile hierarchy is a compressed copy of desktop rather than a designed experience.

---

## 9. Definition of Done for Batch 01

Batch 01 is complete when:

- the intended brand emotion is explicit;
- the design philosophy is explicit;
- prohibited legacy patterns are explicit;
- AI agents have clear instructions for interpreting the design direction;
- future color, typography, layout and component chapters have a stable foundation.

Batch 01 does not yet define final design tokens. Token implementation must wait for the relevant later chapters.
